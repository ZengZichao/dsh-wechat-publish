# 查阅发布规则速查表

参考页：每条规则对应一个真实踩过的坑。排错时按症状查，改完再发布。给模型执行用的完整契约在 `skills/wechat-publish/SKILL.md`，这里只保留「看到什么、怎么处理」。

| ID | 症状或报错 | 固定做法 |
|---|---|---|
| R01 | 草稿变成无样式的纯文本 | 微信只认内联 `style="..."`，会剥掉 `<style>` 和 class。发布管线用 premailer 内联后再删残留 `<style>`；不要手写外链 CSS |
| R02 | `45004` / `45110` | `digest` 上限 120 **字节**，`author` 上限 8 **字节**，`title` 是 64 **字符**。按字节截断 UTF-8 |
| R02b | 署名变成半个名字 | 字节截断是静默的。三个汉字（9 字节）塞不进 `author`，默认留空 |
| R03 | 正文出现 `\u661f...` 转义串 | 微信不会反转义。请求体必须 `json.dumps(..., ensure_ascii=False)` 并以 `charset=utf-8` 发送 |
| R03b | `43002` / `41002` / 误判「草稿不存在」/ 回读乱码 | 只有 `draft/get`、`draft/batchget` 是 POST + JSON body，`cgi-bin/token` 是 GET + query。回读用 `json.loads(r.content.decode("utf-8"))`，不要用 `r.text` |
| R04 | 摘要空或超长 | 优先级：`--digest` > frontmatter `digest` > 标题 |
| R05 | 标题在正文里出现两次 | 自动去重只匹配 `^#\s+` 的一级标题行；加粗段落形式的标题（`**标题**`）不会被去重，必须手动删首行，补一行出处 |
| R06 | 背景发灰、两侧大留白 | 主题给根节点加了底色和内边距。发布前注入根节点覆盖样式，四个方向与上下内边距都用 `!important` |
| R07 | 表格是灰网格圆角卡片 | 表格覆盖样式必须拼在主题 CSS **之后**（同特异性靠顺序胜出），强制黑字白底三线表、去圆角与阴影 |
| R08 | 公式成片回退成 `\( ... \)` 文本 | Python-Markdown 会把 `$...$` 里的 `<` `>` `&` 转义，MathJax 解不了 `&gt;`。送渲染前必须 `html.unescape()` |
| R08b | 公式里的 `*` 变成斜体或加粗 | Markdown 先于公式渲染吃掉星号。必须在转 HTML **之前**把公式换成占位符，渲染完再还原 |
| R09 | `45166 invalid content` | 微信拒绝正文里任何 `href="#..."` 锚点。管线已剥掉 href、保留其余属性；手拼 HTML 要自己删 |
| R10 | `40137 invalid image format` | 多是假图：爬虫把 404 页存成了 `.png`。上传前校验魔数（PNG/JPEG/GIF/RIFF），不是图片就报错并打印前 32 字节 |
| R10b | `40005 invalid file type hint` | 微信还按文件名扩展名校验。内容是真 JPEG 但叫 `fig1.raw` 照样拒收；扩展名要按魔数推出并改成真实后缀 |
| R11 | 发布时找不到图片，或图片路径变成 `%E7%AC%AC...` | premailer 会编码含中文的本地 `src`。管线只替换 src 值、保留 alt 与 style；整段重建 `<img>` 会丢 alt |
| R12 | `<img>` 结构被破坏、src 错位 | 公式渲染作用于整个 HTML，`alt` 里的 `$...$` 会变成带双引号的 `<svg>`。`alt` 只写短的 `图N`，不放公式和图注 |
| R13 | 上传 1 MB 以上的图 | `media/uploadimg` 单图上限 1 MB，管线不压缩。先用 Pillow 转白底 JPEG、长边 ≤1400、质量阶梯降到 900 KB 以下 |
| R14 | 译文首行加粗标题、图占位插错 | `literature` 开关与「删首行」必须联动；题注与占位行并存时只插一次图；替换前先比题注号与占位号的集合差集 |
| R15 | 章节被悄悄删掉 | `trim_body` 在图片上传前触发且不中断流程，`draft/add` 仍成功。发布前预检体积，发布后回读比对 `<h2>`/`<h3>` 数 |
| R16 | 图例的 `*` / `***` 变成斜体加粗 | 显著性标记是裸星号。逐行断言「未转义星号数为偶」，必要时转义成 `\*` |
| R17 | 没有封面、封面被裁 | 优先用文章自带的封面图；站点被拦或只有竖图时，本地生成 2.35:1（940×400）白底 JPEG |
| R18 | 图插错位置或顺序，自检却通过 | 计数类断言发现不了顺序错。按文档顺序断言题注与图片严格交替，期望清单由本篇源文生成 |
| R19 | 跨会话重发同一篇 | 旧草稿里的 `mmbiz.qpic.cn` 直链同账号可复用，零下载零上传；但 `thumb_media_id` 不能跨草稿复用，封面仍需另传 |

## 两条判读要点

- **公式健康**：`count("<svg") > 0` 不代表渲染成功，MathJax 的错误框也是合法 `<svg>`。判据是正文零 `math-fallback`，且 stderr 没有 `[math] SVG render FAILED`。定界符只支持 `$…$` 与 `$$…$$`，`\(...\)` 会原样留在正文。
- **体积**：512 KB 是 skill 自设的保守线，不是微信硬上限。实测约 640 KB 能正常入库；真要大文就抬高上限重推，失败的 `draft/add` 不产生草稿。
